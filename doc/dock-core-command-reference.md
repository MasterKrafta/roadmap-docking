# Справочник команд `dock-core`

Документ описывает публичный перечислимый тип `DockCommand` из `crates/dock-core/src/dock_command.rs`. В текущем исходнике у него 34 варианта. Команды выражают намерение изменить раскладку или явно объявленное временное UI-состояние; саму операцию выполняет `Layout::apply`.

Это справочник по API ядра, а не утверждение о готовности всех пользовательских жестов в приложении. Наличие команды не означает, что к ней уже подключены кнопка, событие мыши или клавиатуры в GPUI.

## Как выполнять команды

Обычный путь применения команды:

```rust
let outcome = layout.apply(command, &metrics)?;
```

Если действие должно участвовать в Undo/Redo текущей сессии, следует применять его через `UndoRedoHistory::apply(&mut layout, command, &metrics)`, а не напрямую через `Layout::apply`.

Применение команды в `Layout::apply` транзакционное: ядро работает с кандидатом, нормализует и проверяет получившуюся раскладку и заменяет текущую только после успешной проверки. Ошибка не должна оставлять частично изменённое дерево. Невалидные цели, значения и структуры отклоняются.

Успешный вызов возвращает `CommandOutcome`:
- `changed_nodes` — узлы, чьё постоянное представление изменилось;
- `new_version` — версия раскладки после операции;
- `actual_value` — фактическое значение для некоторых ограниченных операций изменения размера;
- `inverse` — необязательная команда обратного действия для потребителей, использующих командную отмену.

Ошибки возвращаются как `CommandError`: например, отсутствующий узел/экземпляр панели/плавающая группа, недопустимая цель или значение, неподдерживаемая операция для профиля либо невалидная итоговая раскладка.

## Идентификаторы и основные типы параметров

- `PanelKey` — логический ключ панели, используемый для её повторного открытия.
- `PanelId` — ID конкретного экземпляра панели в текущей раскладке.
- `NodeId` — ID узла дерева, например группы вкладок или колонки.
- `FloatingGroupId` — ID плавающей композиции.
- `DropTarget` — семантическая цель перемещения: например, вставка вкладки, целевая группа, позиция в рейке или край dock.
- `DropZone` — зона стыковки относительно целевой группы; используется командой разделения.
- `DockSide` — левая или правая сторона главного dock.
- `ColumnMode` — развёрнутая колонка, рейка с подписями или рейка только с иконками.
- `ChromeMode` — режим видимости chrome приложения.
- `Rect`, `Point`, `Size` — геометрия в логических пикселях.
- `PanelConstraints` — ограничения панели, которые учитываются ядром при размещении и изменении размеров.

## 1. Панели и вкладки

### `OpenPanel { key, constraints, target }`
Создаёт/открывает экземпляр панели с указанным логическим ключом и ограничениями. Если `target` задан, панель направляется в указанное место. Если `target: None`, ядро пытается восстановить её последнее место, известное в текущем runtime-сеансе; если это невозможно, используется место по умолчанию профиля. Последнее место runtime не следует путать с сохранённым состоянием workspace.

### `ClosePanel { panel }`
Закрывает один экземпляр панели. Ядро удаляет его из раскладки и нормализует затронутые структуры: например, пустая группа вкладок может быть удалена. Последнее известное место докинга используется для последующего повторного открытия в рамках runtime-сеанса.

### `CloseGroup { group }`
Закрывает все панели, принадлежащие указанной группе вкладок, и удаляет группу. Не означает закрытие всей плавающей композиции, если в ней есть другие группы.

### `ActivateTab { group, panel }`
Делает указанную панель активной вкладкой указанной группы. Панель должна принадлежать этой группе.

### `ReorderTab { group, panel, to_index }`
Перемещает вкладку на точный индекс внутри той же группы, не вынося её в другую группу. Индекс относится к итоговому порядку вкладок.

### `MovePanel { panel, target }`
Перемещает существующую панель в семантическую цель `DropTarget`. В зависимости от типа цели это может быть перестановка вкладки, перенос в другую группу, создание группы/колонки или размещение на краю dock. Валидность цели и итогового дерева проверяет Core.

### `MovePanelFromFlyout { panel, target }`
Завершает перенос панели, начатый из открытого flyout. Выполняет тот же перенос, что и `MovePanel`, и закрывает flyout в той же транзакции. При отклонённой операции flyout остаётся без изменений.

### `FloatPanelFromFlyout { panel, bounds }`
Завершает перетаскивание панели из flyout в свободную область: создаёт для неё плавающую композицию в заданных границах. Это отдельный путь завершения жеста из flyout; он не равнозначен простому закрытию flyout.

## 2. Группы, колонки и разделители

### `MoveGroup { group, column, index }`
Перемещает целую группу вкладок в указанную колонку на заданную позицию среди её групп. Индекс назначения также может выражать вставку в рейку и её порядок, если целевая колонка находится в режиме рейки.

### `MoveGroupToMainColumn { group, side, index }`
Перемещает целую группу в заданную позицию списка колонок главного dock с указанной стороны. Если исходная группа является единственной в своей колонке и перенос выполняется на ту же сторону, ядро может переставить существующую колонку, а не создавать дубликат.

### `MergeGroup { group, target_group, index }`
Объединяет исходную группу с целевой группой вкладок, вставляя её панели в точный индекс. Контейнер исходной группы удаляется, но узлы панелей и их экземпляры сохраняются. В профиле Photoshop успешное объединение также разворачивает свёрнутую целевую группу.

### `SplitGroup { group, target_group, zone, ratio }`
Размещает одну группу рядом с другой, образуя разделение. `zone` определяет ориентацию и порядок частей, а `ratio` задаёт желаемое отношение размеров. Операция всё равно подчиняется правилам структуры дерева, профиля и минимальных размеров.

### `ResizeGroups { column, boundary_index, delta, available_height }`
Перемещает границу между соседними группами внутри колонки. `delta` — знаковое смещение в логических пикселях. `available_height` — высота, доступная группам после вычитания промежутков разделителей. Core ограничивает результат с учётом минимальной высоты развёрнутых групп и фиксированной высоты свёрнутых.

### `ResizeColumn { column, width }`
Задаёт желаемую ширину колонки, расположенной у внешнего края главного dock, обращённого к canvas. Фактическая ширина может быть ограничена минимумами/максимумами содержимого. Для изменения границы между внутренними соседними колонками предназначена `ResizeColumnBoundary`.

### `ResizeColumnBoundary { side, boundary_index, delta }`
Сдвигает границу между соседними колонками главного dock на указанной стороне. `boundary_index: 0` означает границу между колонками с индексами 0 и 1; `delta` — знаковое смещение. Ядро ограничивает размеры и сохраняет корректное распределение ширины.

### `ResetColumnRatios { column, available_height }`
Сбрасывает доли высоты групп одной колонки: свободная высота распределяется между развёрнутыми группами, а свёрнутые сохраняют фиксированную высоту. `available_height` описывает высоту, доступную для расчёта.

### `ResetMainColumnRatios { side }`
Сбрасывает горизонтальные доли/распределение ширины колонок главного dock на указанной стороне.

### `RestoreGroupRatios { column, ratios }`
Восстанавливает точный ранее сохранённый вектор долей групп колонки. Это низкоуровневая команда для восстановления состояния и истории; для пользовательского изменения размера предназначены `ResizeGroups` и `ResetColumnRatios`.

## 3. Создание и управление плавающими композициями

### `Float { node, bounds }`
Отделяет узел `Panel` или `Tabs` от текущего места и помещает его в плавающую композицию с заданными границами. Допустимая форма итоговой плавающей структуры определяется активным профилем.

### `FloatGroupAsColumn { group, bounds }`
Отделяет целую группу вкладок в плавающую композицию с одной колонкой. Предназначена, в частности, для случая, когда исходная колонка сохраняет другие группы. Существующий узел группы и его содержимое сохраняются.

### `FloatPanelAsGroup { panel, bounds }`
Отделяет одну вкладку из многовкладочной группы в отдельную группу внутри плавающей композиции с одной колонкой. Исходная группа должна сохранить хотя бы одну вкладку.

### `MoveFloating { group, origin }`
Перемещает плавающее окно, задавая новое начало координат. Размер окна не изменяется.

### `ResizeFloatingBounds { group, bounds }`
Атомарно задаёт новое начало координат и размер плавающего окна. Подходит для изменения размера за верхнюю/левую границу или угол, где одновременно меняются позиция и размер.

### `ResizeFloating { group, size }`
Задаёт желаемый размер плавающего окна без непосредственной передачи новой позиции. Размер может быть ограничен минимальными размерами композиции.

### `RaiseFloating { group }`
Поднимает плавающую композицию на передний план, изменяя её положение в Z-порядке.

### `DockFloating { group, target }`
Стыкует плавающую композицию с заданной целью в dock. Разрешённость операции определяется целью, профилем и правилами структуры раскладки.

## 4. Сворачивание групп и режимы колонок

### `CollapseGroup { group, collapsed }`
Сворачивает или разворачивает группу вкладок, не удаляя её детей и не меняя выбранную активную вкладку. Ядро сохраняет состояние размера/долей родительского контейнера согласно контракту команды. Распознавание двойного клика относится к UI-адаптеру; сам Core принимает только команду с уже определённым значением `collapsed`.

### `SetColumnMode { column, mode }`
Переключает колонку между режимами `Expanded`, `IconsAndLabels` и `IconsOnly`. Изменяет режим представления и соответствующую геометрию ширины, но не перестраивает дерево групп/вкладок и не меняет активные вкладки. Самостоятельного автоматического выбора порогов по движению мыши эта команда не выполняет.

## 5. Flyout рейки

Flyout — временно раскрываемая область, связанная с панелью, выбранной через иконку рейки. Его отображаемый выбор не означает активацию этой панели в её исходной группе вкладок.

### `OpenFlyout { column, panel }`
Открывает flyout для конкретной панели, представленной в рейке указанной колонки. Изменяет временное состояние отображения; не меняет `active_index` родительской группы.

### `CloseFlyout`
Явно закрывает текущий flyout независимо от политики автоматического скрытия.

### `DismissFlyout`
Пытается скрыть flyout в ответ на пассивное действие пользователя, например клик снаружи или Escape. Если автоматическое скрытие отключено, команда игнорируется. UI-адаптер должен распознать событие и отправить эту команду.

### `SetFlyoutAutoCollapse { enabled }`
Включает или выключает автоматическое скрытие при клике снаружи, по Escape и при повторном выборе той же иконки. Это временная настройка UI; она не создаёт запись Undo/Redo.

### `ResizeFlyout { panel, width }`
Запоминает желаемую ширину flyout для конкретного экземпляра панели. Ширина ограничивается объявленными ограничениями панели. Команда временная: не меняет дерево dock, версию раскладки или историю Undo/Redo.

## 6. Видимость chrome приложения

### `SetChrome { mode }`
Задаёт режим видимости chrome приложения через `ChromeMode`, не перестраивая дерево dock. Это команда изменения состояния, но сама по себе она не означает, что клавиша Tab/Shift+Tab уже подключена в GUI: обработчик клавиатуры должен выбрать нужный режим и отправить команду.

## Разница между постоянными и временными действиями

Постоянные команды меняют структуру/состояние раскладки и могут записываться в сессионную историю Undo/Redo. Состояние flyout и его политика автоматического скрытия являются временным UI-состоянием. В частности, `SetFlyoutAutoCollapse` и `ResizeFlyout` явно не записываются в историю; flyout хранится отдельно от постоянного дерева.

`UndoRedoHistory` хранит в памяти контрольные снимки постоянного состояния раскладки. Это отдельный API, а не варианты `DockCommand`. История не сохраняется в workspace.

## API, который не является вариантом `DockCommand`

Следующие возможности предоставляются отдельными типами или методами Core и не должны восприниматься как дополнительные варианты команды:

- Проверка раскладки — методы валидации `Layout`.
- Расчёт прямоугольников/геометрии — `compute_rects` и связанные типы результата.
- Расчёт зон стыковки — `compute_drop_zones`, `DropZone`, `DropTarget`.
- Разрешение и управление жестом перетаскивания — `DragSession`, `DragPayload`, `DragDropRequest`, `DragDropAction` и связанные типы. Начало/движение/отмена жеста должны быть связаны с обработчиками интерфейса.
- Undo/Redo — `UndoRedoHistory`.
- Сериализация и загрузка workspace — `WorkspaceFile`, `WorkspaceLayout` и связанные типы, доступные при включённой feature `serde`.

## Известные отсутствующие команды и границы API

В текущем перечислении `DockCommand` отдельной команды для следующих действий нет:

- **Закрыть всю плавающую композицию целиком** одной операцией. `CloseGroup` закрывает лишь одну группу, а нормализация пустой плавающей области после удаления последних панелей не заменяет явную команду «закрыть окно».
- **Автоматически менять режим колонки при пересечении порога ширины.** `SetColumnMode` позволяет задать режим, но пороги и реакция на ширину должны быть реализованы/определены выше уровня этой команды.
- **Сохранить workspace в файл или загрузить его с диска** — это отдельный API и ответственность приложения за файловый жизненный цикл.
- **Непосредственно обработать мышь, двойной клик, Tab/Shift+Tab или Escape.** Core предоставляет команды и модели состояния; распознавание пользовательского ввода выполняет UI-адаптер.
