# Photoshop Dock UI — roadmap второго прохода

**Цель:** довести GPUI-адаптер до визуального и интерактивного поведения из Photoshop dock spec (разделы 1–12), исправляя по одному небольшому, проверяемому этапу.

**Граница работ:** Core считается реализованным. Не переписывать дерево, нормализацию, валидацию, геометрию или разрешение drop в GPUI. UI должен использовать Core-команды и `LayoutRects`. Если в ходе проверки окажется, что конкретной операции действительно не хватает в Core API, сначала зафиксировать точный пробел и не заменять его вторым алгоритмом в UI.

## Правила рабочего цикла

1. Выполняем **только один этап за раз**. Отдельный коммит содержит одну законченную визуальную/поведенческую правку и относящиеся к ней тесты.
2. Я вношу изменение в `main`, даю SHA коммита и перечисляю ручные проверки.
3. Ты синхронизируешь ветку, запускаешь проверки и смотришь приложение. Следующий этап не начинаем, пока текущий не прошёл или пока явно не записали конкретный блокер.
4. Если визуально плохо, это полноценный дефект даже при зелёных unit-тестах. Численные тесты Core не заменяют ручную проверку GPUI.
5. Не объединять несвязанные изменения и не отмечать шаг выполненным без подтверждённой проверки. Я не буду утверждать, что cargo-тесты прошли, если они не запускались в локальной среде.

## Начальная фиксация по текущему main

Это первичные наблюдения по коду, ещё не результаты визуальной проверки:

- `crates/dock-gpui/src/render.rs`: обычная группа рисует дополнительную строку с названием/ручкой/меню **над** отдельной полосой вкладок. Это расходится с целевой анатомией группы и, вероятно, занимает лишнюю высоту.
- Там же drop-зоны в основном изображаются залитыми прямоугольниками, а поверх добавляется маленькая точка/маркер курсора. Геометрия Core уже различает `Center`, `Top`, `Bottom`, `ColumnLeft/Right`, `TabInsertion`, `FreeArea` и другие типы, но визуальная форма пока недостаточно отражает смысл зоны.
- `app/src/main_window.rs`: `Tab`/`Shift+Tab` сейчас ведут фокус вперёд/назад; их поведение скрытия chrome из спецификации не подключено к этому обработчику.
- Команда Core `SetColumnMode` существует, но в текущем UI пока не найден видимый элемент, который переключает режим колонки.
- У флайаута есть явная кнопка закрытия и обработка `Esc`; click-away требует отдельной проверки/подключения.
- Недавний per-column scroll commit добавил настоящие scroll-контейнеры для Core-overflow. Это пока **не считать визуально подтверждённым**: надо проверить нижние элементы, клики и drag/drop при прокрутке.
- Большая часть текущего UI ещё напоминает демонстрационный renderer: несколько символов заменяют специализированные controls, меню и состояния. Исправляем постепенно, без полномасштабной переписи.

## Этап 1 — исправить анатомию одной группы (первый реальный патч)

**Файлы:** прежде всего `crates/dock-gpui/src/render.rs`; при необходимости отдельные визуальные метрики в `crates/dock-gpui`.

- [ ] Убрать дублирующую строку с названием активной панели над полосой вкладок.
- [ ] Сделать единую верхнюю полосу группы: вкладки, активное состояние и меню справа.
- [ ] Заменить многоточие на читаемую кнопку меню панели; не смешивать её с drag-зоной.
- [ ] Сделать свободное место полосы зоной захвата всей группы; сохранить отдельную тонкую drag-зону над полосой, если это нужно для надёжного захвата.
- [ ] Сохранить ярлык каждой вкладки и единственную активную панель; содержимое рендерить только по прямоугольнику Core.
- [ ] Двойной клик по вкладке и свободному участку полосы должен вызывать один и тот же `CollapseGroup`.
- [ ] Свёрнутая группа показывает только полосу вкладок, без дополнительной строки и без пустого пространства.

**Автотесты:** тесты pure helper для выбора активной вкладки/подписи и доступные renderer-тесты. Не пытаться «тестировать красивость» через один численный тест.

**Ручная проверка:** обычная группа с 1 и 3 вкладками; переключение вкладки; меню справа; перетаскивание за свободное место; двойной клик по вкладке и по пустому участку; сворачивание и восстановление.

**Готово, когда:** группа визуально состоит из полосы вкладок и панели; лишнего второго заголовка нет, меню не конфликтует с захватом, высота соответствует Core. После твоей проверки остановиться и не переходить к этапу 2 до подтверждения.

## Этап 2 — визуальная иерархия, отступы и размеры dock

**Файлы:** `crates/dock-gpui/src/render.rs`, тема/метрики UI; Core-метрики не дублировать локальными числами.

- [ ] Привести фоны dock, группы, активной/неактивной вкладки, панели и разделителей к ясной иерархии.
- [ ] Убрать декоративные рамки/заливки, которые делают каждый прямоугольник отдельной карточкой, если это не соответствует схеме Photoshop.
- [ ] Проверить, что tab strip/header/content используют прямоугольники и высоты Core, а не отдельно рассчитанные альтернативные размеры.
- [ ] Визуально согласовать тонкую границу группы и разделитель; не путать border группы с hit-зоной изменения размера.
- [ ] Соблюсти логические размеры, не вводить DPI-зависимые константы.

**Ручная проверка:** одна колонка/три группы; две колонки; узкая рейка рядом с развёрнутой колонкой; окно 100%, 125%, 150%, 200% scale, если доступна эта настройка.

**Готово, когда:** dock читается как единая панельная область, группы отделены аккуратно, лишние внутренние карточки и лишняя высота не конкурируют с содержимым.

## Этап 3 — рисовать drag-индикаторы по типу Core drop zone

**Файлы:** `crates/dock-gpui/src/render.rs`; при необходимости маленькие pure helper-функции с тестами.

- [ ] `Center`: рамка/подсветка группы, не сплошная непрозрачная заливка всего содержимого.
- [ ] `Top`/`Bottom`/`ColumnEnd`: тонкая горизонтальная линия в точном месте создания группы.
- [ ] `ColumnLeft`/`ColumnRight`/`DockEdge`: вертикальная линия в месте появления новой колонки.
- [ ] `TabInsertion`: вертикальный маркер между вкладками, привязанный к точному insertion index.
- [ ] `RailInsertion`: горизонтальный маркер между значками рейки.
- [ ] `FreeArea`/`FloatingCenter`: контур будущего плавающего окна; не показывать обычные dock-индикаторы над холстом.
- [ ] Удалить постоянный маленький квадрат/точку у курсора, если он не несёт отдельного полезного смысла.
- [ ] Обрезать индикаторы по соответствующему dock/column/float viewport и границам главного окна.
- [ ] Сохранять активную цель визуально отличимой от возможных целей; форма должна показывать действие, цвет только усиливает её.

**Автотесты:** преобразование типа `DropZone` в тип индикатора; координаты/обрезка линий; вставка перед/после вкладки.

**Ручная проверка:** медленно провести панель над центром группы, верхним/нижним краем, краями колонок, между вкладками, над рейкой и над холстом.

**Готово, когда:** до отпускания очевидно, что именно произойдёт, и применённая операция совпадает с индикатором.

## Этап 4 — точность drag/drop и отмены

**Файлы:** `app/src/main_window.rs`, вызовы Core drop API; Core менять только при доказанном отсутствии контракта.

- [ ] Для каждой позиции pointer-up заново получать цель из той же актуальной геометрии, а не полагаться на устаревшую preview-цель.
- [ ] Сверить визуальные координаты после прокрутки с координатами Core и drop overlay.
- [ ] Проверить, что бросок панели/группы на своё место — `NoOp`, без записи undo и без мерцания раскладки.
- [ ] При достижении максимума колонок не показывать индикаторы создания колонки.
- [ ] Не показывать горизонтальную стыковку там, где Photoshop-профиль её запрещает.
- [ ] Проверить `Esc`, потерю фокуса и отпускание вне допустимой цели: исходная раскладка остаётся прежней.
- [ ] Проверить drop в центр свёрнутой группы согласно выбранной политике Core; по спецификации по умолчанию группа раскрывается.
- [ ] Проверить drag из flyout: старт не должен самовольно закрывать flyout или менять раскладку; применять ровно одну команду после отпускания.

**Автотесты:** регрессии на `NoOp`, один command на успешный drop, отсутствие command при cancel, корректное преобразование координат scroll.

**Готово, когда:** нет «прыжка» между индикатором и результатом; отмена не меняет модель; запретные цели недоступны.

## Этап 10 — scroll и clipping по Core overflow

**Файлы:** `crates/dock-gpui/src/render.rs`, `app/src/main_window.rs`.

**Готово, когда:** фактическая видимая область, интерактивные зоны и Core geometry совпадают при прокрутке.

## Этап 11 — меню панели и открытие/закрытие

**Файлы:** `app/src/main_window.rs`, `crates/dock-gpui/src/render.rs`, панельный registry.

**Готово, когда:** нет дубликатов и пустых групп, меню выполняет понятные операции, а содержимое закрытой панели можно восстановить.

## Этап 12 — итоговая матрица композиций и регрессия
