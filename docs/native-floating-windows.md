# Нативные плавающие окна

## Текущая реализация

Плавающие композиции принадлежат модели `NextDockWindow` и отображаются в отдельных GPUI-окнах. Windows-специфичный жизненный цикл находится внутри единственной реализации `crates/dock-gpui/src/next_dock/`:

- `floating_window.rs` отображает содержимое одной плавающей композиции.
- `native_floating.rs` создаёт и повторно использует скрытые PopUp-поверхности, назначает им native owner, переносит/масштабирует их и управляет видимостью.
- `window.rs` хранит состояние композиций и связывает их с главным окном и обработчиками взаимодействия.

## Создание и повторное использование

Перед открытием главного окна подготавливается скрытая floating-поверхность. Когда композиция отделяется, свободное подготовленное окно получает её идентификатор, позицию и размер, после чего показывается. Когда композиция больше не нуждается в отдельном окне, поверхность скрывается и возвращается в пул для повторного использования.

Нативное окно создаётся как GPUI `WindowKind::PopUp` без собственной системной строки заголовка. Перемещение и изменение внешнего размера выполняются средствами Windows; внутреннее содержимое продолжает отрисовываться через GPUI.

При закрытии активного floating-окна обработчик запрашивает возврат композиции в основную поверхность, а саму подготовленную поверхность оставляет доступной для повторного использования.

## Границы текущей архитектуры

- Единственным владельцем дерева и состояния композиций является `NextDockWindow`; отдельное окно отображает назначенную ему композицию.
- Модель дерева находится в `next_dock/model.rs` и пока не использует команды или контроллер `dock-core`. Core предоставляет только общие геометрические типы.
- Windows API изолирован в `next_dock/native_floating.rs` и подключается только на Windows. Остальные части модели и рендеринга не должны напрямую вызывать Win32 API.
- `app` в текущем workspace запускает отдельный crate `dock-experiment`; этот документ описывает именно `dock-gpui` и не меняет точку входа приложения.

## Проверки

После изменений нативных окон локально проверьте:

- запуск главного окна и предварительное создание скрытой floating-поверхности;
- отрыв композиции и повторное использование подготовленного окна;
- перенос и resize нативного окна;
- возврат композиции при закрытии её окна;
- закрытие главного окна вместе с принадлежащими ему floating-окнами;
- отсутствие оставшихся видимых окон после завершения приложения.
