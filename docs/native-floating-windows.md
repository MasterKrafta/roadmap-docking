# Нативные плавающие окна и межоконный dock

## Текущая архитектура

Каждый `FloatingGroupId` может отображаться в отдельном системном окне GPUI. `MainWindow` остаётся единственным владельцем layout, истории Undo/Redo и сохранения workspace. Плавающие окна подписываются на владельца и отправляют команды ему; независимой копии layout у них нет.

Основные файлы:

- `crates/dock-gpui/src/floating_window.rs` — view одной floating-группы, собственный viewport, обработчики жестов и маршрутизация команд в главное окно.
- `crates/dock-gpui/src/main_window/floating.rs` — жизненный цикл нативных окон, согласование геометрии, преобразование координат экрана в систему main dock и ввод для внешних drag-жестов.
- `crates/dock-gpui/src/layers/floating.rs` — рендер floating-группы отдельно от цикла рендеринга всех групп; в нативном окне используются локальные координаты.
- `crates/dock-gpui/src/frame.rs` — `prepare_main_dock_resolver` строит drop-зоны для внешнего перетаскивания без невидимой геометрии floating-групп.
- `crates/dock-gpui/src/dock/controller.rs` и `dock/drag_session.rs` — единая Core drag-сессия и признак того, что жест начат из нативного окна.

## Межоконное перетаскивание

Внешнее перетаскивание использует существующий `DockController` и штатный механизм разрешения drop-зон. Позиция курсора переводится из клиентских координат исходного системного окна в координаты главного dock. Внешний resolver исключает геометрию плавающих окон, которые больше не рисуются на main surface; этим предотвращается попадание в невидимую drop-зону под окном-источником.

Для возврата плавающей композиции в основной dock у окна есть небольшая кнопка-захват «⇲». Она всегда передаёт `DragPayload::FloatingGroup` и `DragHandle::FloatingCapture`: переносится всё плавающее дерево, а не только выбранная Tabs-группа. Для корня `Tabs` геометрия drop-зон строится по этой группе; для корня `Split(Y)` из Tabs-групп — по верхней группе стека. Сами заголовки ОС при этом продолжают обычное перемещение окна.

## Границы и оставшаяся проверка

- Обработчик использует единый layout и сохраняет drop через обычную команду/историю; движение или resize самого системного окна синхронизирует bounds без отдельных Undo-шагов.
- Нативный view в демонстрационном `run()` по-прежнему использует встроенные placeholder-панели через `NoopHost`. Для реального приложения domain-specific содержимое по-прежнему требует собственного `DockHost`.
- Для плавающего `Split(Y)` Core разрешает возврат в слот основной колонки или icon rail. Зоны слияния с Tabs и групповых краёв для такого корня не показываются, поскольку Core их отклоняет.
- Горизонтальные Generic-композиции (`Column` / `Split(X)`) пока не получают кнопку захвата в старом GPUI-адаптере: для их отдельных правил docking нужен отдельный resolver, а не подмена целого дерева одной группой.
- После изменения межоконного drag нужно проверить локально: отрыв кнопкой «⇲» из Tabs и Split(Y), отпускание стека в слот main Column или rail, перетаскивание отдельной вкладки/группы из нативного окна, отмену по отпусканию без цели, отсутствие drop под окном-источником и корректность Undo/Redo после успешного drop.

## Проверки

Локальные проверки выполняются в окружении разработчика. Для текущего этапа:

```bash
cargo fmt --all -- --check
cargo test -p dock-gpui --all-features
cargo test --all-features
```
