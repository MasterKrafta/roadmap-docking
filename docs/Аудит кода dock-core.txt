- OpenPanel разворачивает целевую свернутую Photoshop-группу; размещение по умолчанию ищет Tabs справа, затем слева, и только потом создает новую правую колонку.

- Вставка группы без явного split ratio сохраняет относительные пропорции существующих групп; добавлены регрессионные тесты для слияния floating stack в Column. Оставшиеся ограничения (не считаются закрытыми)
-----------------------------------------------
- Добавлен DropZoneResolver: он один раз строит DropZoneTreeIndex и drop-зоны, а затем разрешает несколько позиций указателя без повторной валидации дерева и аллокации зон. Для этого вызывающий код должен хранить resolver в течение drag-сессии; текущий GPUI-адаптер еще не подключает drag/drop обработку.
- `compute_rects` теперь мемоизирует `minimum_node_size` в локальном кэше одной неизменяемой геометрической операции; кэш общий для расчета preferred widths, основного дерева и floating-окон. Добавлен тест `minimum_node_size_cache_reuses_subtree_values`. `find_parent` по-прежнему выполняет линейный обход. Постоянный индекс родителей не добавлялся: внутри транзакции `apply` дерево меняется до увеличения версии, поэтому кэш только по revision мог бы стать устаревшим. Нужен отдельный индекс с явной областью жизни/инвалидацией.
- Перепроверка стоимости Layout::apply: начальный self.validate_cached обычно попадает в кэш после успешной команды, поэтому исходная формулировка о трёх полных validate неточна. Однако normalize_in_place по-прежнему делает полный preflight перед рекурсивной нормализацией и полный validate после неё; вместе с транзакционным клонированием это остаётся O(n). Убирать любой из этих защитных проходов без отдельного контракта проверки/нормализации небезопасно.
- Разделение большого layout/commands.rs на доменные модули и удаление условных веток профилей требуют отдельного рефакторинга с тестами на публичный контракт. Первый локальный шаг выполнен: расчёт долей при вставке соседней группы вынесен в split_sibling_ratios, но профильные ветки и различающаяся логика main-column width по-прежнему остаются в commands.rs.
- Рефакторинг `layout/commands.rs` продолжается небольшими независимыми переносами без изменения логики команд: политики определения допустимой docking-области, валидация `DropTarget` и проверки panel constraints (`allowed_area_for_target`, проверки Column/Tabs/GroupEdge/RailSlot и принадлежности icon rail, `validate_drop_target`, `validate_constraints_allowed_for_target`, `validate_panel_ids_allowed_for_target`, `validate_panel_ids_allowed_for_area`) вынесены в `layout/command_target_policy.rs`; диспетчер вставки узла по `DropTarget` и вспомогательные операции для `RailSlot` (`insert_node_for_target`, `insert_panel_for_rail_slot`, `rail_slot_group_index`) собраны в `layout/command_target_insertion.rs`. Helper `allowed_area_rejection_reason` живёт рядом с policy-проверками. Видимость методов, используемых из `commands.rs`, ограничена `pub(super)`. Методы `insert_group_at_column`, `insert_existing_column_at`, `insert_group_edge` и `merge_group_into_tabs` перенесены в `layout/command_target_insertion.rs`; расчёт ширины для split-ratio перемещён вместе с `insert_existing_column_at`. Общий `split_sibling_ratios` оставлен в `commands.rs`, поскольку используется и другим командным путём. Переносится только организация логики; `commands.rs` остаётся большим, профильные ветки и основная логика команд ещё требуют дальнейшего доменного разделения.
- `ComputeRectsError` сам сохраняет причину ошибки метрик (`InvalidMetrics { reason }`) и полный список ошибок начальной проверки модели (`InvalidLayout { errors }`). Для этого API изменён напрямую: отдельный `ComputeRectsDiagnosticError` и дополнительный `compute_rects_with_diagnostics` удалены; `compute_rects` — единственная точка входа для геометрии и возвращает подробные ошибки. Тип больше не Copy из-за хранения вектора `ValidationError`. Для структурной несогласованности, обнаруженной уже внутри геометрических подопераций, используется отдельный `InvalidLayoutState`. Регрессионные тесты проверяют сохранение причины метрик и деталей валидации. По тому же принципу `PanelKey::new` и `create_initial_layout` теперь являются единственными основными API и возвращают свои типизированные ошибки непосредственно; методы-дублёры для совместимости не сохраняются.
- Публичный API намеренно оформлен через root-level фасад: все 78 production-модулей в `lib.rs` теперь private (`mod`), а используемые публичные типы и функции экспортируются через `dock_core::Type`. `DropZoneResolver` добавлен в корневые re-exports, потому что он является публичным возвращаемым типом `Layout::prepare_drop_resolver`. Проверены source-файлы `dock-gpui`, приложения и вспомогательных crates: прямых импортов вида `dock_core::some_module::Type` не найдено. Это осознанное breaking API изменение, уменьшающее зависимость внешнего кода от структуры файлов; после локальной проверки полного workspace нужно исправить любые оставшиеся интеграционные потребители.
- Не все DockCommand гарантируют inverse; CommandOutcome документирует inverse как best-effort, а UndoRedoHistory использует снапшоты и от наличия inverse не зависит.
- API экспорта требует метрики явно; невалидный `Layout` больше нельзя сериализовать через публичный convenience-метод в workspace-файл, который затем не сможет загрузиться.
