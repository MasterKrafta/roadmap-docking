# Содержимое панелей: demo host и интеграция библиотеки

## Встроенное окно

Функция `dock_gpui::run` запускает встроенное reference/demo окно. Его `WindowHost` подключён к настоящему контроллеру: команды dock, drag, resize и история layout обрабатываются приложением. При этом метаданные панелей и их содержимое делегируются в `NoopHost`.

`NoopHost` использует встроенный реестр `dock_gpui::panels::PANELS`. Тела панелей из `panels::content::render_registered` намеренно показывают универсальную заглушку («Контент: …»), так как у демонстрационного окна нет доменной модели пользовательского приложения. Эти строки не означают, что операции dock или обработчики ввода являются заглушками.

## Встраивание в приложение

Содержимое панелей не нужно добавлять в встроенный реестр. Реализуйте публичный трейт `DockHost` для своего приложения:

- `panel_title` и `panel_icon` возвращают пользовательские подписи и значки по `PanelInstance`;
- `render_panel` возвращает `gpui::AnyElement` с реальным содержимым панели;
- `command`, `close_floating`, `menu`, `drag_start` и `resize_start` связывают chrome dock с контроллером и состоянием приложения;
- если нужны клавиатурный resize и отслеживание drag вне элемента, реализуйте `resize_key`, `surface_mouse_move` и `surface_mouse_up`; их default-реализации предназначены для preview-хостов.

Используйте `DockSurface::new(...).build(&mut host)` или `render_frame_with_host(..., &mut host, ...)` для вывода кадра с пользовательским host. Геометрию кадра можно рассчитать через `FrameGeometry::compute`, чтобы отрисовка и drop-зоны использовали один снимок.

`NoopHost` оставлен для предпросмотров и проверки компоновки: он показывает встроенные placeholder-панели и использует no-op обработчики взаимодействий. Не используйте его в качестве host интерактивного приложения. Встроенный `run()` — готовое демонстрационное окно, а не конфигурируемая точка внедрения пользовательских renderers.
