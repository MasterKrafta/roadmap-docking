# Заметка: рамка у floating-группы во время перетаскивания

Дата заметки: 2026-10-24

## Наблюдение

Во время перетаскивания закреплённой панели и в режиме плавающей группы вокруг представления появляется тонкая светлая рамка.

По текущему коду это **рамка, рисуемая самим GPUI-рендерером**, а не системная рамка Windows.

## Где находится логика

Файл: [`app/src/main_window/tabs_group.rs`](../app/src/main_window/tabs_group.rs)

Сначала общий рендерер определяет, считать ли группу плавающей:

```rust
let is_floating = match mode {
    GroupRenderMode::Layout => super::group_is_floating(layout, group_id),
    GroupRenderMode::DragPreview => true,
};
```

- `GroupRenderMode::Layout` — обычное отображение. Состояние берётся из дерева `dock-core`: `group_is_floating(layout, group_id)` проверяет, принадлежит ли группа плавающей композиции.
- `GroupRenderMode::DragPreview` — временный предпросмотр во время перетаскивания. Он намеренно **не имеет шапки**, но сейчас принудительно считается плавающим, чтобы использовать тот же внешний стиль.

Затем значение `is_floating` включает рамку:

```rust
let group = if is_floating {
    group
        .border_1()
        .border_color(rgb(theme.colors.primary_text))
} else {
    group
};
```

- `border_1()` задаёт тонкую рамку.
- `border_color(rgb(theme.colors.primary_text))` берёт её цвет из основного цвета текста темы. В текущей теме он выглядит светлым, поэтому рамка воспринимается как белая.

## Почему рамка появляется уже во время драга

Предпросмотр использует тот же `tabs_group::render()`, что и группы в раскладке. Вызов передаёт режим `GroupRenderMode::DragPreview`; этот режим задаёт `is_floating = true`, после чего общий блок стилей добавляет рамку.

Это не меняет дерево `Layout` и само по себе не создаёт реальную floating-группу. Это только визуальный режим предпросмотра. Настоящая плавающая группа создаётся командой Core после отпускания мыши.

## Что решить при возвращении к этой задаче

Пока ничего не менять. Позже отдельно определить желаемое поведение рамки:

1. Убирать рамку только у `DragPreview`, сохраняя её у уже созданных floating-групп.
2. Убрать рамку и у предпросмотра, и у floating-групп.
3. Оставить рамку во всех floating-состояниях.

Если нужно убрать её только во время перетаскивания, не следует менять определение floating-состояния в Core. Лучше разделить два независимых решения в общем рендерере: **нужна ли шапка** и **нужна ли рамка**. Тогда `GroupRenderMode::DragPreview` сможет скрывать рамку, не меняя оформление уже созданного плавающего окна.

## Краткий вывод

Источник рамки — сочетание двух участков в `tabs_group.rs`: `DragPreview => true` и условный блок `border_1().border_color(...)`. Сейчас это ожидаемый результат текущего кода; изменение внешнего вида отложено до отдельного решения.
