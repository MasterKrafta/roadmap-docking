# ADR 0003 — архитектурные решения

**Статус:** начальные решения приняты; проверки R0.3 и открытые D4/D5 не закрыты.

1. Crates разделены по границам из `docs/architecture.md`: `dock-core`, `dock-gpui`, `ui`, `app`, `platform-api`, `platform-windows`.
2. `Profile::Photoshop` будет проверять ограниченную иерархию `DockArea → Column → Group/Tabs → Panel`; произвольные вложенные split в этом профиле запрещены.
3. `Column` должна оставаться валидной с одной группой; нормализатор не должен молча схлопывать колонку.
4. Canvas — защищённая область вне dock, не panel/tab/floating group.
5. Floating groups — внутри главного окна; стек вертикальный; нативные окна ОС отложены за пределы MVP.
6. Toolbar, меню и будущий Options bar — фиксированные компоненты `app`, используют общий `Theme`, но не входят в dock.
7. Выбран отдельный crate `ui` для единственного `Theme` (D1).
8. Правило одного `struct`/`enum` на файл применяется ко всем собственным типам.
9. Статический прототип окна идёт до реализации команд (D2); это не означает, что задачи R0.3 или M3 автоматически выполнены.
10. Максимум 4 колонки и метрики 280/200/36 px пока предварительные (D3); подтвердить по реальному Photoshop.
11. Поведение кнопки `×` общего заголовка колонки (D4) открыто до R11.1.
12. JSON или RON для сохранённой раскладки (D5) выбрать до R9.1.
